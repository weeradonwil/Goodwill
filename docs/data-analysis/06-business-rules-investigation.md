# 06 — Business Rules Investigation

## ขอบเขตและวิธีตรวจ
อ่านรายงาน 01–05 ทั้งหมดและตรวจ CSV ต้นฉบับทั้ง 464 Worksheets ซ้ำเฉพาะประเด็น INV, Sales Team, วันที่, Lot Report และ Free/TOTAL โดย parse ด้วย UTF-8 BOM support ข้อสรุปอ้างอิง export snapshot ไม่ได้อ่านสูตรหรือแก้ Google Sheets

## 1. INV เป็น Unique Key ได้หรือไม่

### ยืนยันได้จากข้อมูล
- Transaction sheets มี 9,064 ค่า INV ที่ไม่ว่างและไม่ใช่ placeholder ในแถวที่มี serial; มี 8,697 ค่า INV ไม่ซ้ำ
- 298 ค่า INV ปรากฏซ้ำ รวม 367 occurrences ส่วนเกิน: 27 ค่าเกิดซ้ำภายใน Worksheet เดียวกัน (30 occurrences ส่วนเกิน) และ 275 ค่าเกิดข้าม Worksheets (337 occurrences ส่วนเกิน)
- Transaction data มีทั้ง INV ตัวเลขและ alphanumeric และมีแถวที่ INV ว่างหรือเป็นเครื่องหมายขีด

### ข้อสันนิษฐาน
- INV น่าจะเป็น business identifier ที่ใช้จับคู่ข้อมูลได้ แต่การซ้ำอาจเป็น split/หลายบรรทัดต่อใบ, สำเนาข้ามชีต, การแก้ไขย้อนหลัง หรือข้อมูลซ้ำจริง

### ต้องถามเจ้าของระบบ
- INV ระบุ Bill/ใบส่งของหนึ่งรายการได้ทั่วทั้งระบบหรือไม่?
- ถ้า INV ซ้ำ หมายถึงหลาย shipment/หลายบรรทัด, การแก้ไข, หรือ duplicate?
- INV มีช่วงเลขซ้ำกันตามปี, ทีมขาย, ประเภทเอกสาร หรือระบบต้นทางหรือไม่?

**ข้อสรุป:** ห้ามใช้ INV เป็น Primary Key หรือกำหนด Unique constraint จากหลักฐาน snapshot นี้ ให้ถือเป็น candidate business identifier และยืนยัน uniqueness scope ก่อนออกแบบ constraint

## 2. Sales Team V2 เทียบกับ Legacy

### ยืนยันได้จากข้อมูล
| รายการ | Legacy: ข้อมูลทีมเซล | V2: ข้อมูลทีมเซล V2 |
|---|---:|---:|
| ขนาด worksheet | 5,612 × 6 | 6,613 × 22 |
| แถวที่มี INV | 5,098 | 6,379 |
| INV ไม่ซ้ำภายในชีต | 5,083 | 6,379 |
| ฟิลด์ที่เห็นชัด | INV, วันที่นำจ่าย, ชื่อร้านค้า | เดือน, วันที่, INV, ร้าน/ที่อยู่/จังหวัด, Free/ยอด 2KG, EVM, UHT, 400G และอำเภอ/เขต |

- INV ที่ซ้ำส่วนเกินใน Legacy มี 15 occurrences ใน 9 ค่า INV; V2 ไม่มี INV ซ้ำภายใน snapshot
- สองชีตมี INV ตรงกัน 1,561 ค่า; Legacy-only 3,522 ค่า และ V2-only 4,818 ค่า
- Transaction INV match กับ Legacy 4,315 ค่า และกับ V2 5,068 ค่า
- Legacy ระบุวันที่ว่า “วันที่นำจ่าย”; V2 ใช้หัวคอลัมน์ทั่วไป “วันที่” และรูปแบบวันมีทั้ง YYYY-MM-DD กับ D/M/YYYY

### ข้อสันนิษฐาน
- V2 ดูเหมือนเก็บข้อมูลเชิงพาณิชย์/ยอดสินค้าและข้อมูลลูกค้าเพิ่ม ส่วน Legacy มีวันที่นำจ่ายชัดกว่า จึงอาจเป็นคนละ grain หรือคนละวัตถุประสงค์
- จำนวน INV ที่ทับกันไม่พอจะสรุปว่า V2 เป็นการแทน Legacy

### ต้องถามเจ้าของระบบ
- Legacy และ V2 ใครเป็นเจ้าของข้อมูลและใช้ในขั้นตอนงานใด?
- V2 ถูกสร้างมาแทน Legacy, เป็นยอดขายรายเดือน, เป็นข้อมูลส่งสินค้า หรือเป็นสำเนาเพื่อรายงาน?
- คอลัมน์ Free/ยอดหมายถึงจำนวนหน่วยเดียวกับจำนวนใน Lot transaction หรือไม่?
- คอลัมน์สุดท้ายที่ header เป็น “0” หมายถึงอะไร?

**ข้อสรุป:** ข้อมูลสองชีตยังใช้แทนกันไม่ได้จากหลักฐานปัจจุบัน ควรเก็บ source และ mapping แยกกันจนกว่าจะยืนยันกฎการรวม/ทดแทน

## 3. วันที่ใน 207 Worksheets ที่ไม่มีคอลัมน์วันที่

### ยืนยันได้จากข้อมูล
- 207/460 transaction worksheets ไม่มีคอลัมน์วันที่นำจ่ายใน header
- 205 ชีตมีชื่อ Worksheet ที่ parse เป็นวันที่ได้
- Worksheet 31/07/259 มีชื่อไม่สมบูรณ์ แต่บรรทัดหัวเรื่องใน CSV ระบุ 31/07/2569
- Worksheet ชีต467 ไม่มีวันที่ทั้งในชื่อชีตและหัวเรื่องที่ export มา
- เมื่อจับคู่ INV กับ Legacy พบ 341 row comparisons ใน 16 ชีต; วันที่ในชื่อชีตตรงกับฟิลด์ “วันที่นำจ่าย” ของ Legacy 337 รายการ และไม่ตรง 4 รายการ
- เมื่อเทียบชื่อชีตกับ V2 วันที่ตรงกัน 679 จาก 3,993 row comparisons; มี 3,314 รายการไม่ตรง และ 39 จาก 205 ชีตที่มีชื่อวันที่ไม่มี V2 วันที่ที่ตรงกันเลย

### ข้อสันนิษฐาน
- ชื่อ Worksheet เป็นแหล่ง candidate ที่มีประโยชน์ แต่ยังต้องยืนยันว่าเป็นวันที่นำจ่ายจริงทุกกรณี
- การตรงกัน 337/341 กับ Legacy สนับสนุนว่า Legacy “วันที่นำจ่าย” อาจเป็นแหล่งยืนยันสำหรับ INV ที่ join ได้ แต่ยังมีตัวอย่างไม่ตรง 4 รายการ
- V2 “วันที่” น่าจะเป็นคนละแนวคิดหรือมีความหมายต่างจากวันนำจ่าย เพราะการเทียบกับชื่อชีตไม่ตรงส่วนใหญ่

### ต้องถามเจ้าของระบบ
- สำหรับ 207 ชีต ชื่อชีตหรือบรรทัดหัวเรื่องเป็นวันที่นำจ่ายที่เชื่อถือได้หรือไม่?
- วันที่ใน Legacy และ V2 หมายถึงวันสร้าง Bill, วันขาย, วันจ่าย หรือวันนำส่ง?
- กรณี 4 รายการที่ Legacy date ไม่ตรงชื่อชีต และชีต467 ควรตัดสินจาก source ใด?

**ข้อสรุป:** ใช้วันที่จากชื่อชีตเป็น candidate พร้อมบันทึก provenance; อย่าเติมเป็นวันจริงโดยอัตโนมัติจนกว่าจะยืนยันกฎ ส่วนชีต467 ยังไม่มีวันที่ระบุได้จาก export นี้

## 4. Lot Report มีโครงสร้าง/ความสัมพันธ์อย่างไร

### ยืนยันได้จากข้อมูล
- Lot Report Evap 2026/05/10 มี 110 × 26 ช่อง; header มี INV, ร้านค้า, กลุ่ม EVM/Creamix/400 กรัม, BBF, pallet, จำนวนลัง และ QA
- พบ 25 แถวที่มี INV และมีค่า INV ไม่ซ้ำ; มี 58 แถวต่อเนื่องที่มีข้อมูลสินค้าแต่ช่อง INV ว่าง
- 24/25 ค่า INV อยู่ในชุด transaction; SG002500518 ไม่พบใน transaction export
- 23 ค่า match กับ Legacy และ 0 ค่า match กับ V2 ใน snapshot นี้

### ข้อสันนิษฐาน
- รายงานมีลักษณะจัดกลุ่มด้วย invoice header แล้วตามด้วยแถวรายละเอียด lot/pallet ที่สืบทอด INV จากแถวก่อนหน้า
- Lot Report น่าจะเป็นรายงาน/การตรวจ lot ของ transaction บางส่วน มากกว่าจะเป็น master ตาราง Lot แยกต่างหาก แต่ยังยืนยันไม่ได้

### ต้องถามเจ้าของระบบ
- แถวต่อเนื่องที่ไม่มี INV ให้ผูกกับ INV ก่อนหน้าจนถึงแถวเริ่ม INV ถัดไปหรือไม่?
- รายงานนี้เป็น snapshot ของ delivery, รายงานเฉพาะสินค้า หรือข้อมูลกรอกแยก?
- SG002500518 เป็น INV จริงหรือมี typo/ไม่อยู่ใน export ชุดนี้?

**ข้อสรุป:** มีหลักฐาน join ด้วย INV 24 ค่า แต่ 1 ค่า unmatched; ยังไม่กำหนด FK และต้องยืนยัน grain ของ lot/line ก่อน

## 5. Free–TOTAL คำนวณอย่างไร

### ยืนยันได้จากข้อมูล
ตรวจเฉพาะแถวที่มี INV ใน V2:

| กลุ่มสินค้า | ทั้ง Free/ยอดปกติ/TOTAL เป็นตัวเลข | สมการ Free + ยอดปกติ = TOTAL |
|---|---:|---|
| 2KG | 420 | ตรง 420, ไม่ตรง 0 |
| EVM | 428 | ตรง 428, ไม่ตรง 0 |
| UHT | 7 | ตรง 7, ไม่ตรง 0 |
| 400G | 2 | ตรง 2, ไม่ตรง 0 |

ในแถวที่ TOTAL และอย่างน้อยหนึ่งองค์ประกอบเป็นตัวเลข แต่อีกช่องว่าง สมการยังตรงเมื่อสมมติว่าช่องว่างเท่ากับศูนย์: 308 (2KG), 373 (EVM), 230 (UHT), 2 (400G)

### ข้อสันนิษฐาน
- ผลตัวเลขสนับสนุนสูตร TOTAL = Free + จำนวนปกติ
- การถือช่องว่างเป็นศูนย์ยังเป็นสมมติฐาน; CSV แสดงค่าที่ export แล้วแต่ไม่เปิดเผยสูตรต้นฉบับ

### ต้องถามเจ้าของระบบ
- Free คือของแถมที่เพิ่มจากยอดปกติหรือรวมอยู่ในจำนวนส่งแล้ว?
- ช่องว่างหมายถึงศูนย์, ไม่เกี่ยวข้อง, ไม่ได้กรอก หรือสูตรคืนค่าว่าง?
- หน่วยของ 2KG/EVM/UHT/400G และ TOTAL เป็นลัง, กล่อง, หรือหน่วยอื่น?
- TOTAL ใน Google Sheets เป็นสูตรหรือกรอกเอง?

**ข้อสรุป:** สมการตรงทุกกรณีที่ทดสอบได้ แต่ยังไม่ควร hard-code formula หรือแปลง blank เป็น 0 จนกว่าจะยืนยันนิยาม

## 6. Record grain ของแต่ละกลุ่ม

### ยืนยันได้จากข้อมูล
- **Lot/transaction:** CSV มีเลขลำดับ, INV/ร้านค้าในแถวหลัก และ product blocks หลายชุดในแถวเดียว; มี INV ซ้ำและแถว INV ว่าง จึงไม่ใช่หนึ่ง INV ต่อหนึ่ง CSV row ในข้อมูลที่เห็น
- **Sales Team Legacy:** แถวที่มี INV 5,098 แถวและ 5,083 ค่า INV ไม่ซ้ำ แสดงว่ามี INV ซ้ำใน row set
- **Sales Team V2:** แถวที่มี INV 6,379 แถว; INV unique ใน snapshot
- **Lot Report:** 25 แถวเริ่ม invoice + 58 แถวต่อเนื่องที่มี item fields
- **แบบฟอร์ม:** มีโครงสร้างหน้ากรอก ไม่ใช่ operational record set ที่ยืนยัน

### ข้อสันนิษฐาน
- Transaction row อาจเป็นรายการส่ง/ร้านค้าภายใน worksheet; product columns อาจเป็น lot quantities ใน record เดียวหรือมี subtotal/continuation
- Sales Team V2 อาจเป็น summary ระดับ invoice แต่ยังไม่ทราบว่า row คือ bill, order หรือ sales allocation
- Lot Report มี grain แบบ invoice group + continuation lot rows

### ต้องถามเจ้าของระบบ
- หนึ่งแถวใน daily Lot sheet แทน shipment, invoice, store delivery หรือ product line?
- หากหนึ่ง INV มีหลายแถว/หลายสินค้า แถวเหล่านั้นเป็น split delivery หรือ detail ของ Bill เดียวกัน?
- หนึ่ง lot row ผูกกับ product + BBF + pallet หรือระดับใด?
- QA ใช้กับทั้ง shipment, invoice หรือ pallet?

**ข้อสรุป:** ระบุ grain ขั้นสุดท้ายไม่ได้จาก export อย่างเดียว; ต้องยืนยัน business event ก่อนออกแบบตาราง

## 7. INV, Bill, Lot และ Sales Team

### ยืนยันได้จากข้อมูล
- ไม่พบ worksheet group หรือ header field ชื่อ Bill โดยตรงใน export; ฟิลด์รหัสที่เห็นชัดคือ INV
- INV มี overlap ระหว่าง transaction กับ Legacy (4,315) และ V2 (5,068)
- Lot Report 24/25 INV match กับ transaction
- Legacy/V2 overlap 1,561 INV

### ข้อสันนิษฐาน
- INV อาจเป็นเลข Bill/ใบส่งของ แต่ยังไม่มีหลักฐานว่าคำว่า Bill และ INV เป็น entity เดียวกัน
- Sales Team เชื่อมกับ delivery ผ่าน INV ได้ในระดับ candidate; Lot Report เชื่อมผ่าน INV ได้บางส่วน
- Store name ไม่เหมาะเป็น join key โดยลำพัง

### ต้องถามเจ้าของระบบ
- Bill คือเอกสารชนิดใด และ INV เป็นเลขเดียวกันหรือคนละเลข?
- Bill หนึ่งใบมีได้หลาย shipment/หลาย lot/หลายร้านหรือไม่?
- Sales Team row ระบุผู้รับผิดชอบการขาย, order, หรือยอดจัดส่ง?

## สรุปข้อจำกัด
ข้อมูลนี้ยืนยันการ match และรูปแบบที่ปรากฏใน CSV เท่านั้น ไม่ได้ยืนยัน business rules, สูตรต้นฉบับ, การใช้ Hidden sheets หรือความหมายของวันที่จาก Google Sheets metadata
